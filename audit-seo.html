Point d'attention — Redirections legacy

Les routes /missions, /medias, /photos, /reseaux, /twitter, /arte, /sources, /carte, /local-guide sont redirigées côté client via <Navigate replace>. Si Googlebot indexait ces URLs sans exécuter JS, il ne verrait pas le redirect. Vérifier que le .htaccess du serveur Apache contient les 301 côté serveur correspondants.

Mission 03Diagnostic de Désalignement

Pages à refonte profonde (3 pages)

Ces pages sont actuellement hors-sujet par rapport au positionnement Méditerranée / Apnée / Dépollution ou présentent des problèmes structurels bloquants.

🔴 Refonte urgente
/communaute
Page Communauté sans H1
La page agrège des stats de réseaux sociaux (Instagram 24k, TikTok 21k, Facebook 64k) dans une logique de "preuve sociale". Aucune requête transactionnelle ne cible "communauté environnementale marseille". Le H1 est totalement absent — erreur critique pour le signal sémantique. À transformer en landing "Rejoindre le mouvement / Bénévolat" ancrée sur le Silo 2.
🟡 Hors scope
/local-guide-marseille
Google Local Guide — Orthogonal aux silos
Page entièrement dédiée au statut "Local Guide Niveau 10". Positionnement orthogonal aux deux silos : ni photographie artistique, ni dépollution. H1 générique ("Google Local Guides" — 3 mots). Peut fonctionner comme page E-E-A-T de crédibilité, mais doit recevoir un noindex ou être recentrée sur la valeur documentaire pour la Méditerranée.
🔴 Thin content + H1 absent
/carte-calanques
Carte Interactive — Page sans H1 et contenu indexable insuffisant
Page techniquement bien structurée (iframe Google My Maps + contenu éditorial) mais sans H1 — erreur critique. Le title est bon, mais le contenu indexable se résume à une légende de carte et des liens externes. Google perçoit une page de "thin content". Nécessite un H1 explicite + un bloc éditorial enrichi (contexte des sites de dépollution, biodiversité observée) pour exister pleinement dans le Silo 2.

Anomalies de structure à corriger sans attendre (3 points)

  • ⚡
    H1 sous-optimisé — /sauver-marseille-documentaire-arte

    H1 actuel = "Documentaire ARTE" (2 mots). Perd tout le potentiel de la requête navigationnelle "Sauver Marseille ARTE pollution". Le titre de la page est excellent, mais le H1 doit reprendre les mots-clés cibles : ex. "Pollution : il faut sauver Marseille ! — Documentaire ARTE avec Karim Saari".

  • 🔒
    noindex non documenté — /actualites

    La page est intentionnellement en noindex: true dans seo.js (flux X/Twitter = thin content dynamique). Correct techniquement, mais ce paramètre doit être commenté explicitement dans le code pour ne pas être supprimé par erreur lors d'une future refonte.

  • 📄
    Pages légales sans noindex explicite — /mentions-legales & /confidentialite

    Ces pages utilisent le DEFAULT_SEO fallback (title et description génériques de l'accueil). Elles doivent être déclarées dans SEO_PAGES avec noindex: true, nofollow: true pour éviter toute indexation parasite et dilution du budget de crawl.

Référence technique Glossaire — Core Web Vitals & Métriques Performance

Ce glossaire recense les métriques de performance clés utilisées dans ce rapport et par Google pour évaluer l'expérience utilisateur. Pour un diagnostic SEO technique complet, l'ensemble de ces indicateurs doit être mesuré et optimisé.

CLS
Cumulative Layout Shift — Stabilité visuelle
Core Web Vital officiel · Signal de classement Google
Score actuel
0 ✓

Mesure la quantité de déplacements inattendus des éléments visuels pendant le chargement de la page. Un élément se "déplace" lorsque sa position change après avoir été affiché (ex. : un texte qui saute parce qu'une image se charge au-dessus).

≤ 0,1
✓ Bon
0,1 – 0,25
⚠ Amélioration
> 0,25
✗ Mauvais

Impact sur ce site : CLS = 0 (parfait). Les images ont des dimensions prédéfinies (width/height) et le Suspense React réserve l'espace avant le chargement. Aucune action requise.

INP
Interaction to Next Paint — Réactivité aux interactions
Core Web Vital officiel depuis mars 2024 (remplace le FID) · Signal de classement Google
Score actuel
N/D

Mesure le délai entre une interaction utilisateur (clic, appui, saisie clavier) et le prochain affichage à l'écran. Contrairement au FID qui mesurait uniquement le premier clic, l'INP mesure toutes les interactions sur toute la durée de la session.

Sur un site de photographie, les interactions critiques sont : l'ouverture d'une lightbox, la navigation dans une galerie, les clics sur le menu mobile. Si des scripts tiers (GTM, pixels) bloquent le thread principal, l'INP grimpe au-delà du seuil.

≤ 200 ms
✓ Bon
200 – 500 ms
⚠ Amélioration
> 500 ms
✗ Mauvais

Impact sur ce site : Non mesuré (données CrUX insuffisantes). Avec un TBT de 250 ms causé par GTM (253 ms) et les pixels tiers, l'INP est probablement supérieur à 200 ms. Action prioritaire : différer les scripts tiers (P1 dans le plan d'action) réduira directement l'INP.

TBT
Total Blocking Time — Temps de blocage total
Métrique Lighthouse (lab) · Proxy de l'INP en conditions de laboratoire
Score actuel
250 ms ⚠

Mesure la somme du temps durant lequel le thread principal JavaScript est bloqué et ne peut pas répondre aux interactions utilisateur. Une tâche JavaScript bloque le thread si elle dure plus de 50 ms (toute durée au-delà de 50 ms est comptée comme "temps de blocage").

Le TBT est la métrique de laboratoire qui corrèle le mieux avec l'INP (terrain). C'est l'indicateur disponible dans Lighthouse pour estimer l'INP quand les données CrUX sont insuffisantes.

≤ 200 ms
✓ Bon
200 – 600 ms
⚠ Amélioration
> 600 ms
✗ Mauvais

Impact sur ce site : TBT = 250 ms (amélioration nécessaire). Causes identifiées : GTM (253 ms) + karimsaari.com index.js (120 ms) + TikTok Pixel (101 ms) + Facebook Pixel (72 ms). Différer ces scripts peut ramener le TBT sous 100 ms.

TTFB
Time to First Byte — Temps de réponse serveur
Métrique Lighthouse + CrUX · Diagnostic hébergement
Score actuel
~0 ms ✓

Mesure le temps entre la requête HTTP du navigateur et la réception du premier octet de la réponse serveur. Un TTFB élevé indique un problème d'hébergement (serveur lent, base de données), tandis qu'un TTFB faible avec un LCP lent indique un problème de ressources côté client (images lourdes, scripts bloquants).

Diagnostic essentiel : Le TTFB permet de distinguer les deux causes d'une page lente — serveur vs. médias — et d'appliquer la bonne correction. Sans ce KPI, on risque d'optimiser les mauvais éléments.

≤ 800 ms
✓ Bon
800 ms – 1,8 s
⚠ Amélioration
> 1,8 s
✗ Mauvais

Impact sur ce site : TTFB ≈ 0 ms (excellent) grâce au prerender SSR Netlify. Le LCP lent (4,1 s) n'est donc pas dû à l'hébergeur mais au poids des médias et aux scripts bloquants. L'hébergement n'est pas à changer.

Rappel — Métriques déjà présentes dans le rapport

FCP First Contentful Paint

Premier élément visuel affiché à l'écran (texte, image, SVG). Indique que la page commence à se charger pour l'utilisateur.

Cible < 1,8 s · Actuel : 2,7 s
LCP Largest Contentful Paint

Plus grand élément visible dans la fenêtre. Principal signal de performance perçue et de classement Google.

Cible < 2,5 s · Actuel : 4,1 s — élément : H1 principal
Les trois Core Web Vitals officiels Google (2024) : LCP · CLS · INP. Ces trois métriques constituent le signal "Page Experience" utilisé dans l'algorithme de classement. Le TBT et le TTFB sont des métriques Lighthouse complémentaires essentielles au diagnostic mais ne font pas partie des CWV officiels. Le FCP est une métrique de perception de chargement.
